# msglist 设计规范

本文件是**子应用与宿主之间的契约**。宿主侧改动前先读这里。
宿主的视觉与容器规则见《moechat-宿主设计实现方案》（`萌萌兔/`），两者不重叠。

---

## 一、加载方式

宿主**不允许**用 `file://` 加载子应用：Android WebView 在 `file://` 下
会因 CORS 拒绝 ES 模块，`<script type="module">` 直接不执行。

宿主必须把子应用的 `dist/` 目录挂到一个本地 origin 上：

| 端 | 机制 | origin |
| --- | --- | --- |
| Android | `WebViewAssetLoader` | `https://appassets.androidplatform.net/apps/msglist/` |
| macOS / iOS | `WKURLSchemeHandler` | `moechat-app://apps/msglist/` |
| Web 宿主 | 同源静态目录 | 站点自身的路径 |

**推论**：子应用内所有资源引用必须是相对路径。`vite.config.ts` 的 `base: './'` 是硬要求。

### 「安装」的语义

安装 = 构建期把 `msglist/dist/` 复制到宿主资源目录。子应用有没有构建步骤对宿主不可见，
宿主只认「一个静态文件目录」。

复制目标必须写进宿主的 `.gitignore`，副本不入库。

## 二、宿主 → 子应用

宿主在 **documentStart** 阶段注入 `window.moechat`：

```ts
interface HostContext {
  subjectId: string    // 主体 id
  subjectName: string  // 主体名
  spacetime: string    // 时空坐标
  theme: string        // 'dark' | 'light'
  locale: string       // BCP-47，宿主系统语言，如 'zh-Hans-CN'
}
```

| 端 | 注入方式 |
| --- | --- |
| Android | `WebViewCompat.addDocumentStartJavaScript`（老 WebView 降级到 `onPageStarted`） |
| macOS / iOS | `WKUserScript`，`forMainFrameOnly: true`，`.atDocumentStart` |
| Web | 内联 `<script>` 于子应用脚本之前 |

`locale` 由宿主系统语言生成：

- Android `Locale.getDefault().toLanguageTag()`
- macOS / iOS `Locale.current.identifier`（下划线换连字符）

子应用侧读取实现见 `src/host/bridge.ts`。宿主未注入时回落到 `navigator.language`，
所以浏览器直接打开也能跑。

## 三、子应用 → 宿主

```ts
window.moechatHost.post(type, payload)
```

| type | payload | 含义 |
| --- | --- | --- |
| `navigate` | `{ url }` | 请求宿主当前容器换页 |
| `openApp` | `{ appId, args? }` | 请求宿主启动另一个子应用 |
| `log` | `{ level, message }` | 上报日志 |
| `close` | — | 请求收起当前容器 |

方法不存在时子应用静默丢弃——宿主可能没有这个能力，不是错误。

## 四、多语言

**基准语言 zh-Hans**。兜底规则见 `src/i18n/index.ts` 的 `resolveTag`：

```
zh-Hans-CN → zh-Hans        命中
zh-CN      → zh → 未命中     → 基准（简体）
en-US      → en             命中
fr-FR      → 未命中          → 基准
```

子应用侧文案目录是编译期强约束（漏键/错键/多键都是编译错误），
宿主侧语言切换后子应用要跟着变——宿主切换语言时**重新加载** WebView，
或通过注入更新 `window.moechat.locale` 后由子应用自行 `setLocale()`。
本期采用前者（简单、不会漏）。

## 五、颜色

子应用沿用宿主同一套令牌，值抄自 `Theme.kt` / `Theme.swift`：

| 用途 | 值 |
| --- | --- |
| 背景 | `#0A0B0D` |
| 面 / 描边 / 抬升 | 白 5.5% / 10% / 7% |
| 主 / 次 / 三级 / 极淡文字 | 白 92% / 66% / 42% / 28% |
| 主题色（第三象限 社会关系） | `#D65BA6` |

改这些值要**先改宿主**，否则四端出现色差。子应用侧集中在 `src/styles/tokens.css`。

## 六、深链

`?conversation=<id>` 直接打开指定会话。宿主要做「点通知跳到那条会话」时用它，
不必新增协议。

---

## 七、高度

子应用布局一律用 `height: 100%`（html → body → #root → .app 逐级），
**不用 `100vh`**。Android WebView 在子应用容器里对 `100vh` 会算错，
具体现象见《宿主设计实现方案》§9.1。

---

## 八、验收方法上的坑

- 用 headless Chrome 截图验证时，`--window-size` 只改窗口不改布局视口
  （实测 `--window-size=390,844` 得到 `innerWidth: 500`），截图会是「按 500 排版后裁到 390」，
  看起来像 CSS 溢出，实际没有。要么用 CDP 的 `Emulation.setDeviceMetricsOverride`，
  要么改完先量 `document.documentElement.scrollWidth` 再下结论。
- 判断有无横向溢出只看 `scrollWidth` 与 `innerWidth` 是否相等，不要靠看截图边缘。
